# SRS — Квартирник

Упрощённый шаблон IEEE 830: введение, общее описание, требования, трассируемость.

| | |
|---|---|
| Продукт | Квартирник, мобильное приложение (iOS / Android) |
| Документ | SRS |
| Статус | Draft |

Пороги времени, размера файла, 7 дней, 14 дней, 20 МБ и лимит 5 квартир заданы этой версией SRS. Диапазон цены Premium берётся из PRD: 199–499 ₽ в месяц. Остальные числа — планка приёмки, чтобы формулировки проверялись.

## 1. Введение

### 1.1 Назначение

Документ описывает, что должна делать система, чтобы выполнить PRD Квартирника. Это общая опора для разработки, дизайна и тестирования и источник тест-кейсов в RTM.

### 1.2 Область

Входит в версию:

- паспорт квартиры: комнаты, техника, счётчики, показания;
- календарь задач и пуши с выключателями по типам;
- документы, гарантии и напоминание за 14 дней;
- сторона арендодателя и сторона нанимателя, в том числе квартира только с одной из них;
- приглашение другой роли ссылкой на 7 дней;
- совместный доступ: ещё люди той же роли;
- отметка платежа: при двух сторонах чек нанимателя и подтверждение арендодателя, при одной стороне взнос этой стороны;
- закрытие доступа нанимателю с сохранением паспорта у квартиры;
- история обслуживания на Premium;
- режим арендодателя;
- покупка Premium в приложении и лимиты базы;
- четыре готовые сторис.

Не входит (NG-1 … NG-7 в PRD):

- поиск жильца и объявления;
- перевод денег и расчёт ЖКХ;
- чат, веб-клиент, сценарий без сети;
- интеграции с Госуслугами Дом, УК, мастерами и страхованием;
- разные права соучастников одной роли, кроме статуса owner.

### 1.3 Термины

| Термин | Смысл |
|---|---|
| Сторона | Участники квартиры с одной ролью: все арендодатели или все наниматели |
| Owner стороны | Единственный участник стороны, который передаёт этот статус и закрывает доступ другому участнику своей стороны. Owner стороны арендодателя ещё закрывает доступ стороне нанимателя |
| Совместный доступ | Второй и следующие люди той же стороны. Та же роль, что у остальных на стороне |
| Жилец-владелец | Человек в квартире «живу сам». Стороны нанимателя нет, пока он сам её не пригласит |
| Подтверждённый платёж | При двух сторонах арендодатель подтвердил задачу месяца. При одной стороне эта сторона сама внесла платёж месяца |
| Актуальные показания месяца | Одна запись на счётчик на календарный месяц. Новая сдача заменяет предыдущую |
| Штатная сеть | Домашний Wi-Fi или мобильная сеть без искусственной задержки. Пороги 2 и 30 секунд относятся к ней |
| FR / NFR | Функциональное / нефункциональное требование |

### 1.4 Связанные документы

PRD Квартирник описывает, зачем существует продукт: проблема, данные, метрики, аудитория и границы.

## 2. Общее описание

### 2.1 Место в продукте

Квартирник сам является продуктом, а не экраном внутри чужого приложения. Пользователь ведёт одну или несколько квартир. Чужие объявления и дом в целом система не ведёт.

### 2.2 Пользователи

- Арендодатель с одной квартирой на базе и с двумя–пятью на Premium.
- Наниматель, в том числе без арендодателя.
- Жилец-владелец своей квартиры.
- Соучастник стороны после совместного доступа.

Один человек может быть арендодателем в одной квартире и нанимателем в другой.

### 2.3 Допущения и зависимости

Допущения:

- у пользователя есть учётная запись. Канал регистрации этим SRS не задаётся;
- приглашение принимает уже вошедший пользователь;
- день срока считается по календарной дате устройства пользователя;
- точная цена Premium — одно значение внутри 199–499 ₽ в месяц. Сценарий от конкретного числа внутри диапазона не зависит;
- если операционная система не разрешила уведомления, задачи календаря всё равно видны, а пуш считается не доставленным.

Зависимости:

- магазин приложений подтверждает или отклоняет оплату подписки;
- доставка пуша зависит от разрешения системы на устройстве;
- файлы документов, чеков и фото показаний хранятся так, чтобы их мог открыть только участник с правом видеть этот файл.

### 2.4 Ограничения

- Клиент версии — мобильное приложение iOS и Android.
- Без сети сохранение показания, платежа и файла не подтверждается.
- На базе — одна квартира и один человек на сторону.
- На Premium — не больше пяти квартир у платящего пользователя.
- На стороне один owner.
- Человек не состоит на обеих сторонах одной квартиры.

## 3. Требования

### 3.1 Функциональные требования

Формулировка — «система должна». У каждого требования есть критерий приёмки.

#### FR-1. Создание квартиры

Система должна давать создать квартиру арендодателю, нанимателю и жильцу-владельцу. Создатель становится единственным owner своей стороны.

Критерий приёмки. После создания пользователь видит паспорт этой квартиры без второй стороны. В роли арендодателя или нанимателя он owner этой стороны. В режиме «живу сам» он owner единственной стороны, а стороны нанимателя нет.

#### FR-2. Паспорт нанимателя без арендодателя

Система должна давать нанимателю вести паспорт, показания и задачи, пока арендодатель не приглашён.

Критерий приёмки. Наниматель без арендодателя сохраняет показание и видит ту же запись после повторного входа. Задача платежа за месяц есть. Наниматель вносит платёж сам, и задача этого месяца закрывается.

#### FR-3. Квартира «живу сам»

Система должна давать жильцу-владельцу вести квартиру без стороны нанимателя.

Критерий приёмки. В квартире «живу сам» нет участников-нанимателей. Показания сдаёт сам жилец-владелец. Задача платежа за месяц есть, и он вносит платёж сам. Приглашение нанимателя по FR-4 переводит пригласившего в арендодатели этой квартиры и создаёт сторону нанимателя. Уже внесённый платёж этого месяца остаётся закрытым.

#### FR-4. Приглашение другой роли

Система должна по запросу участника любой стороны выдавать ссылку приглашения противоположной роли. Ссылка действует 7 суток с момента создания. Новый человек принимает её и получает приглашённую роль. Если эта сторона ещё пустая, он становится её owner.

Критерий приёмки.

- Авторизованный пользователь, который ещё не в этой квартире, открывает действующую ссылку и видит квартиру в приглашённой роли.
- Ссылка старше 7 суток роль не выдаёт, состав квартиры не меняется.
- Повторный переход того же человека не создаёт второе участие.
- Пользователь, который уже на одной стороне, не принимается на другую сторону этой квартиры.

#### FR-5. Совместный доступ

Система должна на Premium позволять участнику стороны пригласить ещё одного человека в ту же роль. У приглашённого те же действия роли, статуса owner нет. На базе такое приглашение не добавляет человека.

Критерий приёмки.

- На Premium приглашённый открывает ту же квартиру: технику, документы своей стороны и задачи. Квартиры пригласившего, куда его не звали, он не видит. Передать owner, закрыть соучастника или закрыть сторону нанимателя он не может.
- На базе попытка пригласить человека той же роли открывает покупку Premium. Новый участник не появляется.

#### FR-6. Owner внутри стороны

Система должна хранить ровно одного owner на сторону. Owner может передать этот статус другому участнику своей стороны и закрыть доступ участнику своей стороны.

Критерий приёмки. После передачи прежний owner теряет передачу прав, закрытие соучастника и, на стороне арендодателя, закрытие стороны нанимателя. Новый owner эти действия получает. Закрытый соучастник при следующем входе квартиру не открывает. Оставшийся owner открывает.

#### FR-7. Закрытие доступа нанимателю

Система должна позволять только owner стороны арендодателя закрыть доступ всей стороне нанимателя.

Критерий приёмки. После закрытия:

- каждый пользователь ушедшей стороны при следующем запросе квартиру не открывает;
- комнаты, техника, счётчики, показания, документы арендодателя, подтверждённые платежи и история обслуживания остаются у арендодателя в том же составе;
- документ ушедшего нанимателя с видимостью «обе стороны» видит сторона арендодателя и не видит следующий наниматель;
- документ ушедшего нанимателя с видимостью «только моя сторона» не видит никто;
- другой арендодатель без статуса owner это закрытие выполнить не может.

#### FR-8. Комнаты и техника

Система должна хранить комнаты квартиры и технику. Техника привязана к комнате или к квартире без комнаты. Добавляют и редактируют участники обеих сторон.

Критерий приёмки. Комната «Кухня» и техника, привязанная к ней, после сохранения видны второй стороне в том же составе: название комнаты и привязка техники.

#### FR-9. Счётчики

Система должна заводить счётчики типов «электричество», «холодная вода», «горячая вода» и «газ», а также счётчик с названием, которое ввёл пользователь.

Критерий приёмки. В паспорте одновременно могут быть четыре счётчика готовых типов и счётчик с названием «отопление». Все пять видны второй стороне.

#### FR-10. Показания

Система должна принимать показание как число, дату и необязательное фото JPG или PNG. На один счётчик и один календарный месяц есть одна актуальная запись. Новая сдача за этот месяц заменяет прежнюю. Пока в квартире есть наниматель, показание сдаёт сторона нанимателя. Если нанимателя нет, сдаёт сторона жильца.

Критерий приёмки. Вторая сторона видит то же число, ту же дату и открывает то же фото. После повторной сдачи за тот же месяц в списке одна запись, и это последняя. Фото больше 20 МБ или не JPG/PNG не сохраняется, пользователь видит причину, прежняя запись месяца не меняется.

#### FR-11. Календарь задач

Система должна вести задачи квартиры.

- На каждый счётчик в текущем календарном месяце есть задача «Сдать показания», пока нет актуального показания за этот месяц.
- На месяц есть задача «Платёж», пока платёж этого месяца не внесён. Задача есть и при одной стороне, и при двух.
- Участник добавляет задачу обслуживания с названием и датой срока.

Критерий приёмки. Сдача показания снимает задачу этого счётчика за месяц и не снимает задачи других счётчиков. Задачу платежа снимает подтверждение арендодателя, если стороны две, и взнос единственной стороны, если сторона одна. Задача обслуживания видна обеим сторонам, если вторая сторона есть, и стоит в календаре на введённой дате.

#### FR-12. Платёж и чек

Система должна закрывать месячный платёж по составу квартиры. Если стороны две, его закрывает только подтверждение арендодателя. Наниматель может прикрепить чек файлом JPG, PNG или PDF, в том числе без последующего подтверждения задача остаётся открытой, пока арендодатель не подтвердит. Подтверждение возможно без чека. Если сторона одна, платёж вносит она сама, с чеком или без него, и задача месяца закрывается. Денежный перевод система не выполняет.

Критерий приёмки. При двух сторонах чек виден обеим, а задача закрывается только подтверждением арендодателя. Это подтверждение считается отмеченным платежом для BG-1. Наниматель при живом арендодателе подтверждение не выполняет. При одной стороне наниматель, арендодатель или жилец-владелец вносит платёж сам, и задача месяца закрывается. Такой взнос живую квартиру по BG-1 не создаёт: для неё по-прежнему нужны обе стороны.

#### FR-13. Пуши и их настройка

Система должна слать не больше одного пуша на открытую задачу в календарный день её срока. Типы пушей: показания, платежи, обслуживание, сроки документов. У нового пользователя все четыре включены. Каждый пользователь выключает и включает типы отдельно.

Кому уходит пуш, если тип у этого пользователя включён и задача ещё открыта:

- показания — стороне, которая сдаёт показания по FR-10;
- платежи — стороне, которая ещё должна закрыть задачу. При двух сторонах это наниматель и арендодатель. При одной стороне это она сама;
- обслуживание — участникам квартиры;
- сроки документов — по FR-15.

Критерий приёмки. В день срока по одной открытой задаче пользователь получает одно уведомление этого типа. На следующий день по той же открытой задаче новое уведомление само не уходит. Если пользователь выключил тип, ему не уходит ни одна задача этого типа, а второму участнику с включённым типом уходит. Выключение пуша задачу из календаря не удаляет.

#### FR-14. Документы

Система должна хранить документ как файл JPG, PNG или PDF до 20 МБ, с названием и типом: договор, чек, гарантия или инструкция. Видимость при загрузке: «обе стороны» или «только моя сторона». По умолчанию выбрано «обе стороны». Дату окончания можно не указывать.

Удаление: автор удаляет свой документ. Участник стороны арендодателя удаляет любой документ квартиры. Наниматель чужой документ не удаляет.

Критерий приёмки. Документ «только моя сторона» есть в списке своей стороны и отсутствует в списке другой стороны, файл по прямой ссылке другой стороне не отдаётся. Документ «обе стороны» открывается у обеих. Наниматель не удаляет документ арендодателя. Арендодатель удаляет документ нанимателя, и тот пропадает у обеих сторон.

#### FR-15. Напоминание о сроке документа

Система должна, если у документа указана дата окончания, создать напоминание на календарный день за 14 дней до этой даты. Без даты окончания напоминания нет.

Критерий приёмки. Для даты окончания 30 ноября напоминание приходится на 16 ноября. В этот день пользователю, который видит документ и у которого включён тип «сроки документов», уходит один пуш. Пользователь, который документ видеть не должен, пуш не получает.

#### FR-16. История обслуживания

Система должна на Premium показывать ленту квартиры: замены техники, задачи обслуживания и подтверждённые платежи. Запись остаётся у квартиры после закрытия доступа нанимателю. На базе лента не открывается.

Критерий приёмки. На базе по команде истории система показывает покупку Premium и не показывает чужие или свои прошлые записи. На Premium замена техники, сделанная до закрытия доступа нанимателю, после закрытия видна арендодателю в том же тексте.

#### FR-17. Режим арендодателя

Система должна показывать пользователю список квартир, где у него роль арендодателя или жильца-владельца. По каждой арендной квартире за текущий месяц видно, сданы ли показания по всем счётчикам и подтверждён ли платёж.

Критерий приёмки. У арендодателя двух квартир в списке две строки со статусами текущего месяца. Квартира, где этот человек только наниматель, в список не входит.

#### FR-18. Лимиты тарифа

Система должна на базе хранить пользователю одну квартиру и одного человека на сторону. На Premium она должна хранить не больше пяти квартир платящего пользователя. Шестая квартира и второй человек стороны на базе не сохраняются.

Критерий приёмки. Вторая квартира на базе не появляется в списке, открывается покупка Premium, первая квартира без изменений. На Premium шестая квартира не сохраняется, пользователь видит отказ из-за лимита 5, прежние пять на месте. Приглашение другой роли при одном человеке на каждой стороне на базе проходит по FR-4 и лимит совместного доступа не тратит.

#### FR-19. Покупка Premium

Система должна продавать Premium внутри приложения. Экран покупки показывает одну цену в месяц в диапазоне 199–499 ₽ включительно. Успешный ответ магазина включает Premium плательщику. Отказ или отмена магазина тариф не меняет.

Платит арендодатель или жилец-владелец. Наниматель платит только в квартире, где арендодателя нет. В квартире, где арендодатель есть, у нанимателя нет сценария покупки. Premium арендодателя открывает совместный доступ и историю на его квартирах обеим сторонам.

Критерий приёмки. После успешной оплаты арендодатель проходит сценарий FR-5 и открывает FR-16. После отказа статус остаётся базой. Наниматель в квартире с арендодателем не доходит до подтверждения магазина. Наниматель единственной стороны без арендодателя доходит до покупки и после успеха приглашает второго нанимателя.

#### FR-20. Сторис

Система должна показывать четыре карточки с темами «Что входит в ЖКХ», «Режимы счётчика электричества», «Страховка» и «Регистрация в квартире». Карточка открывается. Текст карточек пользователь не редактирует.

Критерий приёмки. В разделе сторис видны все четыре названия. Открытие каждой показывает текст этой темы. Других карточек в разделе нет.

### 3.2 Нефункциональные требования

| ID | Категория | Требование |
|---|---|---|
| NFR-1 | Производительность | Экран паспорта уже открытой квартиры появляется не дольше чем за 2 секунды при штатной сети |
| NFR-2 | Производительность | Файл до 20 МБ при штатной сети за 30 секунд либо сохранён, либо отклонён с сообщением. Дольше 30 секунд без итога сценарий не проходит |
| NFR-3 | Данные | Число, дата и фото актуального показания у второй стороны совпадают с тем, что сохранил сдавший |
| NFR-4 | Данные | Успешно загруженный файл открывается у каждого участника, которому он виден по FR-14, и побайтно соответствует загруженному |
| NFR-5 | Надёжность | Если сеть пропала во время сдачи показания, подтверждения платежа или загрузки файла, запись не помечается сохранённой, задача остаётся открытой, пользователь видит сообщение об ошибке |
| NFR-6 | Безопасность | Пользователь без роли в квартире не получает комнаты, технику, документы, показания, задачи и файлы, в том числе по прямой ссылке на файл. После закрытия доступа следующий новый запрос этого пользователя получает отказ |
| NFR-7 | Приватность | Документ «только моя сторона» не входит в список другой стороны и не скачивается ей |
| NFR-8 | Оплата | Покупка Premium не завершается успехом у нанимателя, если в той же квартире есть арендодатель |
| NFR-9 | Уведомления | На одну открытую задачу приходится не больше одного пуша в день срока. Выключенный тип не отправляется этому пользователю |
| NFR-10 | Приглашения | Ссылка возрастом больше 7 суток с момента создания не меняет состав квартиры |
| NFR-11 | Лимиты | На базе не сохраняются ни вторая квартира, ни второй человек стороны. На Premium не сохраняется шестая квартира |
| NFR-12 | Совместимость | Сценарии FR-1, FR-4, FR-10, FR-12, FR-14 и FR-19 дают тот же наблюдаемый результат на актуальных iOS и Android |
| NFR-13 | Данные | У счётчика не больше одной актуальной записи на календарный месяц |
| NFR-14 | Сохранность | После FR-7 у арендодателя тот же набор комнат, техники, счётчиков и записей истории, что сразу до закрытия доступа |
| NFR-15 | Файлы | Файл больше 20 МБ или с типом вне JPG, PNG и PDF не сохраняется. Для фото показания PDF тоже не сохраняется. Пользователь видит, какой запрет сработал |

### 3.3 Внешние интерфейсы

- Учётная запись пользователя — вход перед принятием приглашения. Канал регистрации вне этого SRS.
- Магазин приложений — успех или отказ оплаты для FR-19 и NFR-8.
- Служба уведомлений устройства — доставка пуша, если пользователь и система её разрешили.
- Хранилище файлов — документы, чеки и фото показаний для FR-10, FR-12 и FR-14.
